# KSA Healthcare HR Analytics: Power BI (PBIP) + Excel VBA

> ⚠️ **SYNTHETIC DATA. NOT REAL EMPLOYER DATA.**
> Every employee, salary, facility and figure in this repository was **generated by a script** (`hr-dashboard/build_pbip.py`, `random.seed(42)`).
> "Contoso Health KSA" is a **fictional** organisation; "Contoso" is Microsoft's standard sample-company name.
> This project does **not** use, contain or represent data from **Abeer Medical Group** or any other real company, and it is not affiliated with or endorsed by any employer.
> Facility names use real Saudi city and district names only to make the scenario realistic.

A ready-to-open Power BI Project for HR analytics in a multi-site Saudi healthcare group, plus an Excel VBA edition of the same model. It covers headcount, attrition, recruitment, compensation, training, leave and **Saudization against a 40% Nitaqat-style target**.

## What's inside

| Part | Details |
|---|---|
| **Power BI report** | 6 pages, 82 visuals, Facility / Department / Year slicers on every page |
| **Semantic model** | 8 tables (`Employees`, `Recruitment`, `Training`, `Leave`, `DimDepartment`, `DimFacility`, DAX `Date`, `HR Measures`), **36 DAX measures** in display folders; point-in-time headcount, tenure and payroll |
| **Synthetic data** | 680 employee records (497 active), 170 requisitions, 620 training records, 760 leave records, 8 facilities, 13 departments |
| **Excel VBA edition** | Macro engine (~53,000 employee-month evaluations) that builds snapshots, KPI cards, charts, pivots and a compliance alert register |
| **Python tooling** | `build_pbip.py` regenerates the whole PBIP (data, model, report, theme) from scratch; `validate.py` runs integrity checks; `excel/export_data.py` writes the data workbook |

## Report pages

| Page | What it answers |
|---|---|
| Executive Overview | Headcount, hires, attrition, Saudization and payroll at a glance; trend and facility/department breakdowns |
| Demographics | Age bands, gender split, nationality, tenure; department scorecard |
| Attrition & Retention | Hires vs terminations by month, attrition trend, leaving reasons, hotspot facilities |
| Recruitment | Open requisitions, time-to-fill, offer acceptance, sourcing channels |
| Saudization | Saudization rate vs the 40% target (gauge), by facility and department, Saudi vs non-Saudi trend |
| Rewards & Learning | Salary by grade and department, training hours and completion, leave mix, absenteeism, performance |

## How to open (Power BI Desktop, Windows)

1. Install **Power BI Desktop**.
2. Open `hr-dashboard/KSA Healthcare HR Analytics.pbip`.
3. Click **Refresh** once to load the embedded data. No external files, gateways or credentials are needed.
4. Optional: **Save As** `.pbix` to get a single-file copy.

## Regenerate and validate (any OS with Python 3.10+)

```bash
cd hr-dashboard
python build_pbip.py          # rebuilds data, model, report and theme (deterministic, seed 42)
python validate.py            # JSON, visual-to-model references, measures, M expressions, row counts
pip install openpyxl
python excel/export_data.py   # writes excel/HR_Data.xlsx (one Excel table per entity)
```

To change the scenario, edit the constants at the top of `build_pbip.py` (facilities, departments, salary bands, headcount, Saudization shares) and re-run.

## Excel VBA edition (Windows + Excel)

```powershell
powershell -ExecutionPolicy Bypass -File hr-dashboard/excel/build_xlsm.ps1
```

This builds `KSA Healthcare HR Analytics.xlsm` from `HR_Data.xlsx` and the VBA source in `excel/vba/`. The script temporarily enables Excel's "Trust access to the VBA project object model" setting and restores it afterwards. Dashboard buttons: **Refresh Data**, **Rebuild All**, **Find Employee**, **Export PDF**, **Alerts** (Saudization gaps, attrition ceilings, ageing requisitions, performance watchlist, sick-leave outliers, training no-shows; thresholds on the `Config` sheet) and **Pivot Explorer**.

## Using real HRIS data

Replace each table's partition M query in `KSA Healthcare HR Analytics.SemanticModel/model.bim` with a connector query (Excel, SQL or API) that returns the same column names and types. The report and measures work unchanged.
